# Gluon EVM Agent Guidelines

This repository contains the Solidity smart contracts for the Gluon-EVM protocol. Refer to this file for compilation, style conventions, and architecture constraints.

---

## Tech Stack
- **Framework:** Foundry (Solc `^0.8.20`)
- **Dependencies:** OpenZeppelin Contracts, `forge-std`

## Architecture & Code Style

### 1. Fixed-Point Math (`WAD`)
All oracle prices and protocol fixed-point values are normalized to **18 decimals**. Use `WAD = 1e18` for scaling fixed-point operations:
- **Multiplication:** `(valA * valB) / 1e18`
- **Division:** `(valA * 1e18) / valB`
- **Inversion:** `(1e18 * 1e18) / val`

### 2. Custom Errors
Always use Solidity custom errors instead of `require` statements with strings. Declare them globally or at the top of contracts:

```solidity
error InvalidOracle();

// CORRECT
if (oracle == address(0)) revert InvalidOracle();

// WRONG
require(oracle != address(0), "invalid oracle");
```

### 3. State & Constructor Validations
Move static immutable validations into constructors where appropriate instead of repeatedly checking them inside view or runtime functions.

For Gluon reactors, configuration such as oracle addresses, treasury addresses, fees, reserve-ratio parameters, and required metadata should be validated when the reactor is created.

## Boundaries
- **Dependencies:** Never modify files under `lib/` (OpenZeppelin, `forge-std`, or external protocol dependencies).
- **Autogenerated files:** Never modify JSON files under `out/` or `cache/`.
- **Environment:** Do not commit `.env` or any file containing private keys.
- **Oracle Interface:** Oracle integrations must follow the shared `IOracle` interface.
- **Scope:** Keep pull requests focused on one improvement and avoid unrelated refactoring.

---

## Git Workflow
- **Commit Format:** Follow the **Chris Beams Git Commit Message** guide (imperative subject, capitalized, under 50 characters, wrapped body).
- **Branch Format:** `feat/short-desc`, `fix/short-desc`, or `refactor/short-desc`.
